# Skills 功能

Skills 是 Codex App 里的一个功能，说白了就是把你常用的提示词保存起来，下次直接用一个命令就能调用。就像给 AI 设置了一堆快捷键。

---

## Skills 的作用

你肯定遇到过这种情况：每次让 AI 做某个任务，都要输入一大段提示词，很烦。比如每次代码审查，都要说"请检查代码的安全性、性能、可读性……"，一堆废话。

Skills 就是来解决这个问题的。你把这段提示词保存成一个 Skill，下次直接输入 `/review` 就行了，AI 会自动执行完整的代码审查流程。

### 为什么需要 Skills

**1. 省时间**

不用每次都输入重复的提示词，一个命令搞定。

**2. 标准化**

团队里每个人都用同样的 Skills，确保工作流程一致。比如代码审查的标准、测试的流程，都可以通过 Skills 固定下来。

**3. 不容易出错**

手动输入提示词容易漏掉东西，用 Skills 就不会。每次执行都是完整的流程。

**4. 可以分享**

你写的 Skills 可以分享给团队，大家都能用。新人来了，直接用现成的 Skills，不用重新学习。

## 如何创建 Skills

创建 Skills 很简单，就是在项目根目录创建一个 `SKILLS.md` 文件。

### 基本格式

```markdown
# Project Skills

## /review
检查代码质量：
- 安全漏洞（SQL 注入、XSS 等）
- 性能问题（不必要的循环、内存泄漏）
- 代码规范（命名、格式）
- 潜在 bug（边界条件、异常处理）

## /test
运行所有测试：
1. 运行单元测试
2. 运行集成测试
3. 如果有测试失败，分析原因并给出修复建议

## /deploy
部署流程：
1. 运行测试，确保全部通过
2. 构建项目
3. 上传到服务器
4. 重启服务
5. 验证部署是否成功
```

就这么简单。每个 Skill 用 `##` 开头，后面跟命令名（比如 `/review`），然后写具体的指令。

### 带参数的 Skills

Skills 还可以带参数，更灵活。

```markdown
## /add-feature [feature-name]
添加新功能：
1. 创建功能分支：feature/[feature-name]
2. 生成基础代码框架
3. 添加对应的测试
4. 更新文档
```

使用时：`/add-feature user-profile`，AI 会自动把 `user-profile` 替换到对应位置。

### 条件执行

还可以加一些条件判断。

```markdown
## /smart-deploy
智能部署：
- 如果测试失败，停止并报告错误
- 如果在 main 分支，部署到生产环境
- 如果在 develop 分支，部署到测试环境
- 否则，部署到开发环境
```

AI 会根据实际情况选择执行路径。

## 实用 Skills 示例

这里分享一些实用的 Skills，你可以直接拿去用。

### 代码审查

```markdown
## /review
全面代码审查：

安全检查：
- SQL 注入、XSS、CSRF 等常见漏洞
- 敏感信息泄露（密码、Token）
- 权限控制是否正确

性能检查：
- 不必要的循环和计算
- 数据库查询是否优化
- 内存泄漏风险

代码质量：
- 命名是否清晰
- 函数是否过长
- 重复代码
- 注释是否充分

给出具体的改进建议，标注严重程度（高/中/低）
```

### 测试相关

```markdown
## /test-all
运行完整测试：
1. 运行单元测试
2. 运行集成测试
3. 生成测试覆盖率报告
4. 如果有失败，详细分析原因

## /add-tests [file]
为指定文件添加测试：
1. 分析文件中的所有函数
2. 为每个函数生成测试用例
3. 考虑边界条件和异常情况
4. 确保测试覆盖率达到 80% 以上
```

### 重构相关

```markdown
## /refactor [file]
重构指定文件：
1. 提取重复代码为函数
2. 简化复杂的逻辑
3. 改进命名
4. 添加必要的注释
5. 确保功能不变（运行测试验证）

## /optimize [file]
性能优化：
1. 识别性能瓶颈
2. 优化算法复杂度
3. 减少不必要的计算
4. 优化数据库查询
5. 给出优化前后的性能对比
```

### 文档相关

```markdown
## /doc [file]
生成文档：
1. 为所有函数添加文档注释
2. 说明参数类型和返回值
3. 给出使用示例
4. 注明注意事项

## /readme
生成 README：
1. 项目简介
2. 安装步骤
3. 使用方法
4. API 文档
5. 贡献指南
```

### Git 相关

```markdown
## /commit
智能提交：
1. 查看所有改动
2. 生成清晰的 commit message
3. 按功能分组提交（如果改动较多）
4. 确保 commit message 符合规范

## /pr
创建 Pull Request：
1. 总结本次改动
2. 列出主要变更
3. 说明测试情况
4. 生成 PR 描述
5. 创建 PR
```

### 调试相关

```markdown
## /debug
调试助手：
1. 分析最近的错误日志
2. 定位问题代码
3. 分析可能的原因
4. 给出修复建议
5. 添加必要的日志和错误处理

## /fix-bug [issue-number]
修复 Bug：
1. 查看 Issue 描述
2. 定位问题代码
3. 修复 Bug
4. 添加测试防止回归
5. 更新 Issue 状态
```

## 团队协作技巧

Skills 最大的价值在于团队协作。

### 统一工作流程

团队可以维护一个统一的 `SKILLS.md` 文件，所有人都用同样的 Skills。这样：

- 代码审查标准一致
- 测试流程统一
- 文档格式规范
- 新人上手更快

### 分享最佳实践

团队里有人写了个好用的 Skill，可以分享给大家。慢慢积累，团队的 Skills 库会越来越强大。

### 版本控制

把 `SKILLS.md` 提交到 Git 仓库，跟代码一起管理。这样：

- 所有人都能看到最新的 Skills
- 可以追踪 Skills 的变更历史
- 可以在不同分支使用不同的 Skills

### 项目特定 Skills

不同项目可以有不同的 Skills。比如：

- 前端项目：UI 组件生成、样式检查
- 后端项目：API 文档生成、数据库迁移
- 移动端项目：多平台构建、发布流程

根据项目特点定制 Skills，效率更高。

## 高级技巧

### 组合 Skills

可以在一个 Skill 里调用其他 Skills。

```markdown
## /full-check
完整检查：
1. 运行 /review 检查代码质量
2. 运行 /test-all 确保测试通过
3. 运行 /doc 检查文档完整性
4. 生成检查报告
```

### 上下文感知

Skills 可以根据当前上下文调整行为。

```markdown
## /optimize
智能优化：
- 如果是 Python 代码，检查是否可以用列表推导式
- 如果是 JavaScript，检查是否可以用 ES6+ 特性
- 如果是数据库查询，检查索引使用情况
- 根据代码类型给出针对性建议
```

### 交互式 Skills

Skills 可以在执行过程中询问用户。

```markdown
## /deploy-interactive
交互式部署：
1. 显示当前分支和改动
2. 询问：确定要部署吗？
3. 询问：部署到哪个环境？（生产/测试/开发）
4. 根据选择执行部署
5. 部署完成后询问：是否需要回滚？
```

## 使用建议

### 1. 从简单开始

刚开始不要写太复杂的 Skills，先从简单的开始。比如代码审查、运行测试这种常用的。

### 2. 逐步完善

用的过程中发现哪里不够好，就改进。Skills 是可以不断迭代的。

### 3. 给 Skills 起好名字

命令名要简短、好记、见名知意。比如 `/review` 比 `/code-quality-check` 好记。

### 4. 写清楚指令

Skills 的内容要写清楚，AI 才能准确执行。不要写得太模糊。

### 5. 定期清理

有些 Skills 可能不再需要了，定期清理一下，保持 `SKILLS.md` 简洁。

## 常见问题

### Skills 不生效怎么办？

检查几个地方：

1. `SKILLS.md` 文件是否在项目根目录
2. 格式是否正确（Markdown 格式）
3. 命令名是否以 `/` 开头
4. 重启 Codex App 试试

### 可以有多个 SKILLS.md 吗？

一般一个项目一个 `SKILLS.md` 就够了。如果项目很大，可以按模块分，但不建议搞太复杂。

### Skills 会不会冲突？

如果两个 Skills 命令名相同，后面的会覆盖前面的。所以要注意命名，避免冲突。

## 总结

Skills 是个很实用的功能，能大大提高效率。特别是团队协作时，统一的 Skills 能让大家的工作流程保持一致。

**核心要点：**

- Skills 就是保存常用提示词的快捷方式
- 创建很简单，在 `SKILLS.md` 文件里写就行
- 可以带参数、条件执行，很灵活
- 团队共享 Skills，统一工作流程
- 从简单开始，逐步完善

花点时间整理你常用的提示词，做成 Skills，以后会省很多事。
