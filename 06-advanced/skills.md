# Skills 功能

Skills 是 Codex App 里的一个功能，说白了就是把你常用的提示词保存起来，下次直接用一个命令就能调用。就像给 AI 设置了一堆快捷键。

---

## Skills 的作用

你肯定遇到过这种情况：每次让 AI 做某个任务，都要输入一大段提示词，很烦。比如每次代码审查，都要说"请检查代码的安全性、性能、可读性……"，一堆废话。Skills 就是来解决这个问题的。你把这段提示词保存成一个 Skill，下次直接输入 `/review` 就行了，AI 会自动执行完整的代码审查流程。

为什么需要 Skills？首先是省时间，不用每次都输入重复的提示词，一个命令搞定。其次是标准化，团队里每个人都用同样的 Skills，确保工作流程一致。比如代码审查的标准、测试的流程，都可以通过 Skills 固定下来。而且手动输入提示词容易漏掉东西，用 Skills 就不会，每次执行都是完整的流程。你写的 Skills 还可以分享给团队，大家都能用，新人来了直接用现成的 Skills，不用重新学习。

---

## 如何创建 Skills

创建 Skills 很简单，就是在项目根目录创建一个 `SKILLS.md` 文件。基本格式就是每个 Skill 用 `##` 开头，后面跟命令名（比如 `/review`），然后写具体的指令。

比如这样：

```markdown
# Project Skills

## /review
检查代码质量：安全漏洞（SQL 注入、XSS 等）、性能问题（不必要的循环、内存泄漏）、代码规范（命名、格式）、潜在 bug（边界条件、异常处理）

## /test
运行所有测试：先运行单元测试，再运行集成测试，如果有测试失败就分析原因并给出修复建议

## /deploy
部署流程：运行测试确保全部通过，构建项目，上传到服务器，重启服务，验证部署是否成功
```

就这么简单。Skills 还可以带参数，更灵活。比如：

```markdown
## /add-feature [feature-name]
添加新功能：创建功能分支 feature/[feature-name]，生成基础代码框架，添加对应的测试，更新文档
```

使用时输入 `/add-feature user-profile`，AI 会自动把 `user-profile` 替换到对应位置。

还可以加一些条件判断：

```markdown
## /smart-deploy
智能部署：如果测试失败就停止并报告错误，如果在 main 分支就部署到生产环境，如果在 develop 分支就部署到测试环境，否则部署到开发环境
```

AI 会根据实际情况选择执行路径。

## 实用 Skills 示例

这里分享一些实用的 Skills，你可以直接拿去用。

**代码审查：**

```markdown
## /review
全面代码审查：检查安全问题（SQL 注入、XSS、CSRF 等常见漏洞、敏感信息泄露、权限控制），检查性能问题（不必要的循环和计算、数据库查询优化、内存泄漏风险），检查代码质量（命名是否清晰、函数是否过长、重复代码、注释是否充分），给出具体的改进建议并标注严重程度
```

**测试相关：**

```markdown
## /test-all
运行完整测试：运行单元测试，运行集成测试，生成测试覆盖率报告，如果有失败就详细分析原因

## /add-tests [file]
为指定文件添加测试：分析文件中的所有函数，为每个函数生成测试用例，考虑边界条件和异常情况，确保测试覆盖率达到 80% 以上
```

**重构相关：**

```markdown
## /refactor [file]
重构指定文件：提取重复代码为函数，简化复杂的逻辑，改进命名，添加必要的注释，确保功能不变（运行测试验证）

## /optimize [file]
性能优化：识别性能瓶颈，优化算法复杂度，减少不必要的计算，优化数据库查询，给出优化前后的性能对比
```

**文档相关：**

```markdown
## /doc [file]
生成文档：为所有函数添加文档注释，说明参数类型和返回值，给出使用示例，注明注意事项

## /readme
生成 README：项目简介、安装步骤、使用方法、API 文档、贡献指南
```

**Git 相关：**

```markdown
## /commit
智能提交：查看所有改动，生成清晰的 commit message，按功能分组提交（如果改动较多），确保 commit message 符合规范

## /pr
创建 Pull Request：总结本次改动，列出主要变更，说明测试情况，生成 PR 描述，创建 PR
```

**调试相关：**

```markdown
## /debug
调试助手：分析最近的错误日志，定位问题代码，分析可能的原因，给出修复建议，添加必要的日志和错误处理

## /fix-bug [issue-number]
修复 Bug：查看 Issue 描述，定位问题代码，修复 Bug，添加测试防止回归，更新 Issue 状态
```

## 团队协作技巧

Skills 最大的价值在于团队协作。团队可以维护一个统一的 `SKILLS.md` 文件，所有人都用同样的 Skills。这样代码审查标准一致，测试流程统一，文档格式规范，新人上手更快。

团队里有人写了个好用的 Skill，可以分享给大家。慢慢积累，团队的 Skills 库会越来越强大。把 `SKILLS.md` 提交到 Git 仓库，跟代码一起管理。这样所有人都能看到最新的 Skills，可以追踪 Skills 的变更历史，可以在不同分支使用不同的 Skills。

不同项目可以有不同的 Skills。比如前端项目可以有 UI 组件生成、样式检查的 Skills，后端项目可以有 API 文档生成、数据库迁移的 Skills，移动端项目可以有多平台构建、发布流程的 Skills。根据项目特点定制 Skills，效率更高。

## 高级技巧

可以在一个 Skill 里调用其他 Skills：

```markdown
## /full-check
完整检查：运行 /review 检查代码质量，运行 /test-all 确保测试通过，运行 /doc 检查文档完整性，生成检查报告
```

Skills 可以根据当前上下文调整行为：

```markdown
## /optimize
智能优化：如果是 Python 代码就检查是否可以用列表推导式，如果是 JavaScript 就检查是否可以用 ES6+ 特性，如果是数据库查询就检查索引使用情况，根据代码类型给出针对性建议
```

Skills 还可以在执行过程中询问用户：

```markdown
## /deploy-interactive
交互式部署：显示当前分支和改动，询问确定要部署吗，询问部署到哪个环境（生产/测试/开发），根据选择执行部署，部署完成后询问是否需要回滚
```

## 常见问题

Skills 不生效怎么办？检查几个地方：`SKILLS.md` 文件是否在项目根目录，格式是否正确（Markdown 格式），命令名是否以 `/` 开头，重启 Codex App 试试。

可以有多个 SKILLS.md 吗？一般一个项目一个 `SKILLS.md` 就够了。如果项目很大可以按模块分，但不建议搞太复杂。

Skills 会不会冲突？如果两个 Skills 命令名相同，后面的会覆盖前面的。所以要注意命名，避免冲突。

## 总结

Skills 是个很实用的功能，能大大提高效率。特别是团队协作时，统一的 Skills 能让大家的工作流程保持一致。Skills 就是保存常用提示词的快捷方式，创建很简单，在 `SKILLS.md` 文件里写就行，可以带参数、条件执行，很灵活。团队共享 Skills 能统一工作流程。花点时间整理你常用的提示词，做成 Skills，以后会省很多事。
